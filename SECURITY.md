# Безопасность

Не публикуйте ключи, auth headers, query secrets, signing material и переписку в Issues или логах. Если секрет опубликован, сначала отзовите его у провайдера. Удаление коммита не отзывает ключ.

Секреты профиля шифруются AES-256-GCM через Android Keystore, IV создаётся шифром, provider ID включён в AAD. Backup Android выключен. Keystore может быть аппаратно защищён, но это не гарантируется на каждом устройстве. Ciphertext хранится в приватных SharedPreferences; обычные Room и DataStore секретов не содержат. UI показывает маску и не считывает старый ключ в поле. Ошибка расшифровки не приводит к отправке пустого ключа молча.

Сетевой слой не логирует тело/URL/headers, не следует перенаправлениям, не отключает проверку TLS, не делает автоматический retry generation. В интерфейс возвращаются только безопасная категория и HTTP-код. Локальный HTTP проверяется единым TransportPolicy; в manifest cleartext доступен технически для динамических адресов, но на уровне клиента заблокирован без отдельного согласия и локального literal IP/localhost.

Приватная история не шифруется отдельно. Экспорт без шифрования, clipboard и локальный HTTP имеют риски, явно обозначенные в приложении. Root, malicious accessibility services и compromised OS вне модели защиты. Параметры JSON генерации не предназначены для секретов.

О подозрении на уязвимость сообщайте владельцу репозитория [Amir1502/AstraChat](https://github.com/Amir1502/AstraChat): через Private vulnerability reporting, если владелец его включил, иначе приватным каналом — без публикации деталей в открытом issue. Не прикладывайте реальные ключи и переписку; воспроизводите проблему только тестовыми нерабочими ключами.
